# 生日主题网站 · 秘密基地

一个**浅蓝白色系韩式 ins 风**的生日主题单页网站：奶油白 → 雾霾蓝的柔和渐变底，
漂浮的柔焦光斑与细碎闪点，玻璃拟态卡片，留白多、高级感。

纯 HTML + CSS + 原生 JavaScript，**没有任何构建工具、没有外部 CDN 依赖**，下载即用，可直接丢到 GitHub Pages。

> 说明：除「观赏烟花」页为了衬托烟花保留深暮蓝夜空外，其余页面统一为浅蓝白韩系 ins 风。

**所有页面的背景都有**：缓慢流动的**细碎闪点 + 四角星细闪**（不同延迟、不同周期、波浪式漂移），
以及**漂浮的卡通简笔画**——可爱的**玉米**（三根）和 **5 种甜品**：纸杯蛋糕、甜甜圈、冰淇淋、马卡龙、布丁。
它们会各自以不同的速度、幅度缓慢飘动和轻轻旋转，不影响任何点击操作。

## 一、文件结构

```
/
├── index.html              ← 单文件承载全部页面与逻辑（只需要改这一个文件）
├── bgm/                    ← 背景音乐
│   ├── birthday.mp3        ← 生日快乐歌（密码门 / 第 1 页）
│   ├── bird.mp3            ← 鸟之诗 伴奏（第 2 页 / 第 4 页相册）
│   └── pear.mp3            ← 梨花瘦（第 5 页 时光机）
├── page1/                  ← 第 1 个跨页的照片（1.jpg ~ 18.jpg，18 张）
├── page2/
├── ...
├── page7/                  ← 第 7 个跨页（7 × 18 = 126 张，正好放满）
└── README.md               ← 本文件
```

> 为什么照片和音乐直接放在根目录、没有 `assets/` 这一层？
> 因为用 GitHub 网页上传时，拖进去的文件夹会直接落在仓库根目录（不会自动补出父目录），
> 所以代码已按「`bgm/` 和 `page1~7/` 都在根目录」来读取，和线上结构完全一致。

## 二、怎么换成自己的素材

### 1. 放音乐（超简单，不用改代码）

把 mp3 文件直接丢进 `bgm/`，文件名保持下面三个之一即可自动生效：

| 文件名 | 用在哪一页 |
| --- | --- |
| `birthday.mp3` | 页面 0 · 密码门 / 页面 1 · 生日快乐页（同一首，进入第 1 页不中断） |
| `bird.mp3` | 页面 2 · 三模块基地 / 页面 4 · 游戏相册（同一首，来回切换不中断） |
| `pear.mp3` | 页面 5 · 时光机 |

页面 3 · 观赏烟花沿用进入前的那首音乐，不打断。

**文件不存在或加载失败时不会报错、不会弹窗**，只是静默不出声，右上角的音乐开关按钮依然可以正常点击。

> **关于浏览器自动播放限制**：密码门一进站就会尝试播放 `birthday.mp3`，但手机 / 桌面浏览器
> 通常禁止“用户还没交互就出声”。所以代码会在你**第一次点击、触摸或打字**时再补播一次，
> 也就是说「一动手就有音乐」，不会出现莫名没声音的情况。如果你点了静音，这个补播会跳过。
右上角按钮在页面切换时会保持你的静音选择（你关掉了就一直关着，除非你再打开）。

如果要换文件名或改用别的路径，改 `index.html` 里的：

```js
bgm: {
  birthday: 'bgm/birthday.mp3',
  bird:     'bgm/bird.mp3',
  pear:     'bgm/pear.mp3'
}
```

### 2. 放照片（和放音乐一样：丢进文件夹就行，**不用改代码**）

文件夹已经帮你建好了（`page1` ~ `page7`，就在仓库根目录），直接往里丢图片：

```
page1/     ← 第 1 个跨页（相册翻开的第 1 组左右两页）
     1.jpg   2.jpg   3.jpg     ← 左页第 1 行
     4.jpg   5.jpg   6.jpg     ← 左页第 2 行
     7.jpg   8.jpg   9.jpg     ← 左页第 3 行
    10.jpg  11.jpg  12.jpg     ← 右页第 1 行
    13.jpg  14.jpg  15.jpg     ← 右页第 2 行
    16.jpg  17.jpg  18.jpg     ← 右页第 3 行
page2/     ← 第 2 个跨页，同样命名 1~18
...
page7/     ← 第 7 个跨页
```

**就这么简单，不用打开 `index.html` 改任何东西。** 规则只有两条：

1. **文件夹**：第 N 个跨页 → `pageN/`（仓库根目录下）
2. **文件名**：`1` ~ `18` 的数字（1~9 在左页，10~18 在右页）

补充几点：

- 排版是 **3 × 3**：一个跨页 = 左页 9 张 + 右页 9 张 = **18 张**；
  一共 **7 个跨页 = 126 张**，正好放下你的 126 张照片。
- **放不满 18 张也没关系**，空着的格子会自动显示优雅的虚线占位框，**不会报错**。
- 后缀 `jpg / jpeg / png / webp / gif` 都能自动识别（同一个文件夹里建议统一后缀，会少发几次请求）。
- 建议图片比例 3:4 / 4:5（竖图）或 1:1（方图），显示效果最好。
- 点击照片可以看大图，点遮罩或右上角 × 关闭；键盘 `←` `→` 也能翻页。
- 手机上会自动变成**单页显示**（一次看 9 张，翻页半页半页地走），照片不会小到看不清。

> 想再多放一些（比如 144 张）：把 `index.html` 里 `CONFIG.album.spreadCount` 改成 `8`，
> 再在仓库根目录新建一个 `page8` 文件夹即可。

> 如果你**不想**用「数字命名」这套规则（比如想保留 `IMG_2333.jpg` 这种原文件名），
> 可以打开 `index.html`，搜索 `【最简单用法：把照片丢进文件夹就行，一行代码都不用改】`，
> 在下面的 `spreads: []` 里手写路径，写法和以前一样：
> ```js
> spreads: [
>   { left: ['page1/IMG_2333.jpg','','','','','','','',''],
>     right: ['','','','','','','','',''] }
> ]
> ```
> 只要这里填了内容，就以手写路径为准；保持 `[]` 空数组就是自动扫描文件夹。

### 4. 改文字

所有文案都在 `index.html` 顶部的 `CONFIG` 里，逐条都有中文注释：

| 配置项 | 作用 |
| --- | --- |
| `password` | 密码门密码（默认由 `'2026' + '0222'` 两段拼接而成，连起来正好 8 位） |
| `startDate` | 时光机「至今已 X 天」的起算日期（`YYYY-MM-DD`） |
| `timeline` | 时光轴节点，带 `ellipsis: true` 的是「……」省略节点 |
| `blessings` | 祝福墙便签内容 |
| `wishStorageKey` | 许愿记录在浏览器里的存储键名 |

## 三、部署到 GitHub Pages（手机 + 电脑都能打开）

1. **新建仓库**
   登录 GitHub → 右上角 `+` → `New repository` → 起个名字（例如 `birthday`）→ 选 **Public** → 创建。
   > 免费账号的 Pages 只对 Public 仓库开放；Private 需要付费版。

2. **上传文件（网页上传，注意 100 个文件/次的限制）**
   进入仓库 → `Add file` → `Upload files`，把 `index.html`、`README.md`、`bgm` 文件夹、
   `page1` ~ `page7` 文件夹一起拖进上传框（共 131 个文件 > 100，需分 2 次提交）：
   - 第 1 次：`index.html` + `README.md` + `bgm/` + `page1/` ~ `page4/`（约 79 个）
   - 第 2 次：`page5/` ~ `page7/`（约 54 个）
   > ⚠️ 拖进去的文件夹会直接落在仓库根目录（不会自动补出 `assets/` 父目录），
   > 代码就是按「`bgm/`、`page1~7/` 都在根目录」写的，所以**直接拖即可，不要套任何外层文件夹**。
   也可以在本机用命令：
   ```bash
   git init
   git add .
   git commit -m "birthday site"
   git branch -M main
   git remote add origin https://github.com/你的用户名/你的仓库名.git
   git push -u origin main
   ```
   > 注意：一定要让 `bgm`、`page1~7` 文件夹和 `index.html` 处于**同一个层级**，不要多套一层目录。

3. **打开 Pages**
   仓库页面 → `Settings` → 左侧找到 `Pages` →
   `Source` 选择 **Deploy from a branch** →
   `Branch` 选择 **main**，目录选择 **/ (root)** → `Save`。

4. **等待生成网址**
   等 1～3 分钟，刷新 Pages 页面，顶部会出现绿色提示和网址：
   ```
   https://你的用户名.github.io/你的仓库名/
   ```

5. **访问**
   - 电脑：浏览器直接打开上面的网址。
   - 手机：用微信 / 浏览器打开同一个网址即可，布局会自动适配。
   - 改完文件后重新 Commit，等 1 分钟左右刷新就会更新（可能需要强制刷新缓存）。

### 关于路径

项目里所有资源路径都是**相对路径**（不会出现以 `/` 开头的写法），
所以放在 `https://用户名.github.io/仓库名/` 这种子目录下也能正常加载，不会 404。

### 关于字体

没有引用任何需要额外网络环境的 CDN 字体，中文使用系统字体栈
（`Noto Serif SC` / `思源宋体` / `宋体` / `霞鹜文楷` 等优雅衬线体，逐级回退）。
如果你想让所有设备都显示同一种字体，可以把字体文件（例如 `LXGWWenKai.ttf`）放进
`assets/fonts/`，再在 `index.html` 的 `<style>` 顶部用 `@font-face` 引入。

## 四、隐私提醒（请务必阅读）

- **即使设置了密码，公网页面依然有泄露风险。** 密码只是前端的简单遮挡，任何人拿到网址后
  查看网页源码都能看到密码；搜索引擎、浏览器历史、聊天记录转发也都可能让链接外流。
- **请不要放任何敏感内容**：真实姓名、身份证件、真实住址 / 小区、学校或公司名称、
  手机号、微信号、私密照片、聊天截图等，一律不要上传。
- 页面中所有称呼都使用昵称（周周米玉、玉米周周、周周小弟、阿殊大王等），
  你补充文字 / 照片时也请保持这个习惯。
- 相册里的照片请自行确认不包含可识别的隐私信息（门牌、快递单、工牌、定位水印等）。
- 许愿记录保存在**访问者自己的浏览器**里（localStorage），不会上传到任何服务器，
  换设备 / 清缓存后会消失，这是正常的。
- 如果确实需要更稳妥的保护，请改用带后端鉴权的方案（例如需要登录才能访问的私有页面），
  纯静态页面无法做到真正的安全。
